Resumen (introducción)
Este plan describe la estrategia de pruebas para la versión 3 del Portal Clientes, centrada en el nuevo flujo de pago con tarjeta guardada, 3-D Secure, reembolsos parciales y la descarga de facturas. Cubre las pruebas funcionales y de regresión del ciclo de noviembre y las pruebas de rendimiento del flujo de pago.

Estrategia de automatización
Regresión de UI con Playwright en cada build nocturna. API con colecciones de Postman en el pipeline. Rendimiento del flujo de pago con JMeter antes de cada release. Los casos llevan el tag @ATS_xxx para enlazarlos con los resultados.
Gestión de datos de prueba
Los datos se generan con scripts a partir de un catálogo anonimizado. Las tarjetas de prueba son las del sandbox de la pasarela. Los datos se restauran cada lunes. Nunca se usan datos reales de clientes.
Las tarjetas de tipo «Datos de prueba» del Planificador se vinculan a este apartado.
Gestión de defectos
Los defectos se registran en el Planificador como tarjetas de tipo Defecto, vinculadas al caso que falla. Prioridad: Crítica (bloquea el pago o expone datos), Alta, Media, Baja. Un defecto crítico abierto impide cerrar el ciclo.
