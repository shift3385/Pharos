Quality gate al cerrar un ciclo y tendencia entre ciclos

Respuesta a «¿las métricas solo se usan para bonito?»: no. Con esta propuesta cada métrica alimenta una decisión. Nada de esto está programado todavía; son bocetos.

Tres decisiones que pasan a depender de las métricas

¿Cerramos el ciclo? ¿Sale la versión?El gate evalúa los criterios del plan. Un «No cumple» bloquea el cierre hasta que alguien lo justifica, y la justificación queda firmada en el informe.
¿Dónde miramos primero?La tendencia en Inicio avisa cuando una métrica empeora varios ciclos seguidos o se sale del objetivo del plan.
¿Puede decidir una ejecución sola? (1.0)El mismo gate, con el mismo registro, es el que AUT-05 usará para decidir las ejecuciones desatendidas.

«Cerrar ciclo» está deshabilitado mientras falte una justificación (aquí la de defectos críticos) o un criterio manual sin marcar. Con todo en «Cumple», el aviso es verde («Go») y no se pide nada.

  • Obligatorio (por defecto) cuenta para el veredicto y pide justificación. Orientativo se muestra y queda en el informe, pero ni bloquea ni la pide.
  • Manual: un criterio que no es una métrica («Visto bueno del PO») se marca a mano en el cierre.
  • «Sin datos» (no hay nada que medir) cuenta como «No cumple» en el gate: no se puede cerrar con un criterio sin evidencia sin justificarlo.
  • Las cifras se congelan al cerrar. Reabrir el ciclo conserva el cierre anterior en el historial; volver a cerrarlo crea un cierre nuevo.

Hoy los defectos no guardan cuándo se corrigieron ni cuántas veces se reabrieron. El núcleo lo apuntará en cada cambio de estado (data.lifecycle), y los defectos que ya existen se rellenan una vez desde el registro de auditoría, que guarda el antes y el después de cada estado.

Forma de los datos (a acordar con «plan-iso»)

Acordado con plan-isoSe adopta su forma: data.metrics: PlanMetric[] en el plan, y los criterios apuntan a una métrica con metricId. Nombres: escapedDefects (número) y fixTime (días). La densidad es por cada 100 casos ejecutados. blocking? va en el criterio. Una métrica sin criterio es un objetivo, y la tendencia la dibuja como línea de objetivo. El bloque de abajo es la versión anterior a este acuerdo.

El catálogo de métricas vive en un sitio neutral que es de este track (src/shared/metrics/ y su gemelo en Rust). PLN-06 lo importa para que el plan elija métricas de una lista y no escriba texto libre.

// src/shared/metrics/catalog.ts (este track)
export const METRIC_KINDS = ["executed", "passRate", "coverage", "criticalDefects",
  "defectDensity", "escapeRate", "timeToFix", "reopenRate", "flakyRate"] as const;
export type MetricKind = (typeof METRIC_KINDS)[number];
export type MetricOp = ">=" | ">" | "<=" | "<" | "=";
/** La unidad sale del tipo: % en las tasas, número en defectos, días en timeToFix. */
export interface MetricTarget { kind: MetricKind; op: MetricOp; target: number }

// Plan (test-plan, lo escribe plan-iso): campos OPCIONALES, los planes viejos siguen valiendo
export interface ClosureCriterion {
  criterion: string;              // texto que se muestra (igual que hoy)
  metric: string;                 // «≥ 95%»: se sigue escribiendo para exportar y lectores viejos
  measure?: MetricTarget | null;  // estructurado; ausente o null → criterio manual
  blocking?: boolean;             // por defecto true (obligatorio); false = orientativo
}
// PLN-06, «Métricas y objetivos medibles» (objetivos que no son criterio de salida)
metricObjectives?: (MetricTarget & { note?: string })[];  // la tendencia los dibuja como línea de objetivo

// Ciclo: test_cycles.data.closures[] (JSON ya sincronizado, SIN migración)
interface CycleClosure {
  closedAt: string; closedBy: string;
  verdict: "go" | "goWithRisks" | "noGo";
  planId: string | null; planVersion: string | null;
  criteria: (ExitCriterion & { blocking: boolean; manualMet?: boolean; justification?: string })[];
  metrics: CycleMetrics;          // cifras congeladas: tasa, densidad, escapes, tiempo, reapertura, flaky, conteos
}
// Defecto: data.lifecycle = { fixedAt?, closedAt?, reopens } y data.escaped (casilla en el formulario)
  • Si measure existe, la derivación (derive.rs y su gemelo execution-summary.ts) deja de adivinar por el texto. Con planes viejos se mantiene la lectura actual del texto.
  • Contrato v1: ExitCriterion gana blocking y los tipos nuevos. HomeProject gana trend: CycleTrendPoint[], así que sigue habiendo una sola lectura para Inicio (RED-W6).
  • Órdenes nuevas: cycle_gate_preview y cycle_close (escritorio), y GET /api/cycles/:id/gate y POST /api/cycles/:id/close (web). El cierre se registra en la auditoría con el actor y las justificaciones.
  • No espero migraciones. Si alguna hiciera falta, comprobaré los números libres con check:migrations y lo hablaré con plan-iso. El ADR se numera de la misma forma.

Decisiones que necesito del usuario

D1 · Tres veredictos: Go, Go con riesgos y No-goEl veredicto lo calcula el gate. Con criterios obligatorios incumplidos y justificados, la persona que cierra elige entre «Go con riesgos» y «No-go».
D2 · Criterios obligatorios u orientativosTodos son obligatorios por defecto. El plan puede marcar uno como orientativo: se muestra, pero no bloquea.
D3 · «Sin datos» cuenta como «No cumple» en el gateAsí no se cierra sin evidencia sin dejar una justificación.
D4 · Los escapes se marcan a mano en el defectoUna casilla «Encontrado fuera de las pruebas (escape)». La alternativa sería deducirlo del entorno «producción», pero es frágil porque el entorno es texto libre.
D5 · «Cerrado» deja de estar en el diálogo de ediciónSolo se cierra con «Cerrar ciclo…», que pasa por el gate. Reabrir se sigue haciendo editando el estado.
D6 · Dónde va el gadget, sin scroll en Inicio (UX-27/28)A (recomendada): «Próximas pruebas» y «Criterios de salida» bajan de 19 a 11 filas (siguen por encima de su mínimo) y la tendencia ocupa debajo de ellas 15 × 8. Siguen las 24 filas y se ven los 9 gadgets. B: la tendencia sustituye a «Ejecuciones diarias» en la distribución por defecto (9 × 9), y las diarias pasan a «Gadgets ocultos». C: la tendencia empieza oculta y se añade a mano desde «Gadgets ocultos». En los tres casos, una distribución guardada solo recibe el gadget si cabe en las 24 filas. Si no cabe, el gadget queda oculto y aparece un aviso único: «Nuevo gadget: Tendencia de ciclos». Con A y B, una distribución guardada idéntica a la de ahora pasa a la nueva.
