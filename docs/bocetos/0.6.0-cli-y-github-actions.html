  • La primera línea dice siempre modo, servidor, proyecto y token (solo su prefijo visible). Nadie sube al sitio equivocado sin verlo.

  • Con el modo local, Pharos tiene que estar cerrado hasta que llegue N5. Después, el mismo comando escribe con la app abierta y el run aparece en ella sin recargar.

  • El token, el permiso y el proyecto se comprueban antes de lanzar los tests: un token caducado no se descubre a los 20 minutos.

Boceto 6 · docs/integraciones/github-actions/pharos-pr.yml

La plantilla del criterio de salida: JUnit, SARIF, k6 y axe

.github/workflows/pharos.yml
name: Tests y Pharos
on:
  pull_request:
permissions:
  contents: read            # nada más: el token de Pharos va aparte
jobs:
  tests:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with: { persist-credentials: false }
      - uses: actions/setup-node@949feb2413d6458794dcd2491c4babbbce0c15c1 # v7.1.0
        with: { node-version: 22 }
      - run: npm ci
      - run: npx playwright test --reporter=junit       # → test-results/junit.xml
        continue-on-error: true
      - run: npx eslint . -f @microsoft/eslint-formatter-sarif -o reports/eslint.sarif
        continue-on-error: true
      - run: docker run --rm -v "$PWD:/w" -w /w grafana/k6@sha256:<digest> run --summary-export reports/k6-summary.json perf/smoke.js
        continue-on-error: true
      - run: npx @axe-core/cli@4.10.2 http://localhost:4173 --save reports/axe.json
        continue-on-error: true
      - name: Subir a Pharos
        if: always()
        uses: <owner>/pharos/.github/actions/pharos-report@<sha de 40 caracteres> # v0.6.0
        with:
          server: ${{ vars.PHAROS_URL }}
          token: ${{ secrets.PHAROS_TOKEN }}
          project: PAGOS
          files: |
            test-results/junit.xml
            reports/eslint.sarif
            reports/k6-summary.json
            reports/axe.json
  • Todo uses: va fijado por SHA de 40 caracteres, con la versión en un comentario. Las imágenes, por digest, y las herramientas npm, con versión exacta. Un script del repo lo comprueba en .github/ y docs/integraciones/.
  • La acción pharos-report solo usa bash y curl: no descarga binarios ni usa acciones de terceros. El token entra por env, se enmascara y llega a curl por stdin.
  • Con el job de pruebas fallando, if: always() sube igual los informes; el PR sigue en rojo por los tests, no por Pharos.
  • Hay otras dos plantillas: pharos-matriz.yml (varios jobs al mismo run y un job final que lo cierra) y pharos-cli-windows.yml (pharos watch -- npm test en un runner Windows).

El token no va en el YAML: va en un secreto de GitHub. Crear un token de proyecto…

.github/workflows/pharos.yml
      - name: Subir a Pharos
        if: always()
        uses: <owner>/pharos/.github/actions/pharos-report@<sha> # v0.6.0
        with:
          server: ${{ vars.PHAROS_URL }}
          token: ${{ secrets.PHAROS_TOKEN }}
          project: PAGOS
          files: |
            # cambia estas rutas por las de tu proyecto
            test-results/*.xml
            reports/*.sarif
            reports/k6-summary.json
            reports/axe.json

En GitHub, una vez por repositorio

  1. Settings › Secrets and variables › Actions › New repository secret: nombre PHAROS_TOKEN, valor el token (solo se ve al crearlo).
  2. Pestaña Variables: PHAROS_URL = https://pharos.empresa.com
  3. Pega el paso al final del job que ejecuta tus tests y abre un PR.
El último informe recibido por este proyecto llegó hace 2 h desde «CI GitHub» (RUN-128).
  • Está junto a «Tokens de proyecto» y «Webhooks», de la pista A. Lo ven todos los roles; solo un Test Manager puede crear el token desde aquí.
  • El YAML lo arma una función pura con el servidor, la clave del proyecto y los formatos elegidos. Nunca contiene el token: un test lo comprueba.
  • La línea verde dice si ya llega algo, para confirmar que la conexión funciona sin salir de la app. Es una lectura de runs que ya existe: sin datos nuevos ni migración.
