Reglas del panel
  • Grupos: «Hoy», «Ayer», y después el día con su nombre («Lunes 15 nov»). Cabecera fija al desplazar.
  • Una fila sin leer lleva fondo suave y punto azul. Clic en la fila = abrir el destino y marcar leída.
  • La acción directa depende del tipo: Ver invitación · Revisar · Abrir caso · Ver defecto · Ver informe · Resolver.
  • Si el destino ya no existe (borrado, sin acceso), la acción queda desactivada con el motivo en el tooltip.
  • Varios conflictos de una misma sincronización se agrupan en una sola fila con el número.
  • Leído/sin leer viaja entre tus equipos: lo que lees en el escritorio deja de estar sin leer en la web.
  • No tus propias acciones: cerrar tú un ciclo no te notifica a ti.
  • Sin sonidos ni notificaciones del sistema operativo en 0.5.0.

Qué viaja con la cuenta y qué no
  • Viaja: nombres del perfil (alias, nombre y apellidos), idioma, tema, sombra de tarjetas, opacidad del fondo y fondo «predeterminado / ninguno». Gana el cambio más reciente, aunque se hiciera sin conexión, como el tablero de Inicio (UX-27).
  • Se queda en el equipo: imagen de fondo propia (puede pesar más que el límite de 16 KB), retención de la papelera, sincronización automática y carpeta de descargas: dependen del equipo.
  • Servidor: nuevas claves en user_preferences (ui.language, ui.theme, ui.appearance) y GET /api/me/preferences para traerlas de una vez. Sin migración.
  • Prueba de aceptación: cambiar el idioma en un equipo lo cambia en otro al sincronizar.

AUD-01c · Copia .bak restaurada a mano

Sin pantalla. Cada guardado sube un contador dentro de la base cifrada (sync_state.save_seq) y lo escribe también en un fichero junto a ella (pharos.db.seq, solo el número). Al abrir, si la base trae un contador menor que el del fichero, es una copia antigua puesta encima: se rota el device_id (oplog::rotate_device_id, como ya hace la recuperación con clave) y sus eventos empiezan una cadena nueva.

  • Sin el fichero (primer arranque tras actualizar, o borrado) no se rota nada. Rotar de más es inofensivo: solo abre otra cadena.
  • El diagnóstico exportado anota restoredCopyDetectedAt; el registro de auditoría añade un evento «Copia restaurada detectada».
  • No necesita migración local: la 0044 queda sin usar y pasa a retired.
  • Test: abrir, guardar dos veces, volver a poner el .bak, abrir y editar → verify_chain ve dos cadenas íntegras, ninguna rota.

API de eventos para las pistas W y K

Las notificaciones son de otras personas (te asignan, te piden revisión, te invitan), así que tienen que viajar por el servidor. Dos puertas, con la misma forma:

Cliente (escritorio y web) · @modules/notifications

import { notify } from "@modules/notifications";

await notify({
  kind: "case.review_requested",          // ver tabla
  to: { userIds: [reviewerId] },          // o { workspace: true } = todos los miembros
  workspaceId, projectId,                 // opcionales
  subject: { entity: "test_case", id: caseId, key: "BM-CP-0142", title: "Transferencia…" },
  data: { /* extra por tipo, ≤ 2 KB */ },
});
// Nunca lanza ni bloquea la acción: sin conexión se encola y sale en la próxima sincronización.
// El emisor nunca se notifica a sí mismo; el actor lo pone el servidor desde la sesión.

Servidor · server/src/modules/notifications

import { emitNotification } from "../notifications";

await emitNotification(client /* Pool o PoolClient, dentro de tu transacción */, {
  kind: "invitation.received",
  actorId: req.userId,
  recipientIds: [inviteeUserId],          // o { workspaceId } para todos sus miembros
  workspaceId,
  subject: { entity: "workspace_invitation", id: invitationId, title: workspaceName },
  data: { role: "test_analyst" },
});
kindQuién lo emitePara quiénAcción directa
invitation.receivedW, en el servidor al crear la invitaciónla persona invitadaVer invitación
case.review_requestedK, en el cliente al enviar a revisiónrevisores (o el workspace)Revisar
case.approved · case.changes_requestedK, en el clienteel autorAbrir caso
defect.assignedR, en defectos al cambiar el responsableel responsable, si es miembroVer defecto
cycle.closedR, en «Cerrar ciclo»miembros del workspaceVer informe
sync.conflictR, tras una sincronización con conflictos nuevossolo este equipo (no viaja)Resolver

Hasta que W fusione los miembros, { workspace: true } se resuelve a nadie y solo se aceptan destinatarios que sean el propio usuario. Con W, el servidor rechaza destinatarios que no compartan workspace con el emisor (sin spam entre cuentas). La función de miembros la pone W; R solo la llama.

Plan técnico y reservas

  • Servidor 0023 notifications (id, recipient_id, kind, actor_id, workspace_id, project_id, subject jsonb, data jsonb, created_at, read_at) + rutas GET /api/me/notifications?since=, POST /api/notifications, POST /api/me/notifications/read (ids o todo). Purga a los 90 días. Hace falta un ADR.
  • Local 0043 notifications en el escritorio: copia cifrada de las recibidas, la cola de salida y los conflictos locales. La web lee del servidor y no guarda copia.
  • Papelera: src-tauri/src/trash.rs nuevo (listar, restaurar, eliminar para siempre) que reutiliza la purga de SYNC-06 con plazo 0 y anota cada restauración en el oplog y la auditoría. TrashSection.tsx ampliado. Sin migración.
  • Shell: módulo src/modules/notifications (modelo, API, panel); TopbarControls.tsx solo cambia el «Próximamente» por el panel.
  • Puntos compartidos mínimos: registro de comandos en lib.rs, registro de migraciones en db.rs, dos líneas en db.rs (guardar/abrir) para AUD-01c, la llamada a notify en defectos y ciclos, y un fichero nuevo en src/modules/profile/api/ para SYNC-09 (zona de C: le aviso).
  • Docs: filas de ROADMAP, changes/RED-W2.md, RED-W3.md, SYNC-09.md, AUD-01c.md, manual (barra superior, Administración, Perfil), GLOSARIO, ARCHITECTURE y ADR-0015 (AUD-01c).

Decisiones que necesito

1. ¿Las notificaciones viajan por el servidor?Sin eso solo habría avisos de tus propias acciones y de conflictos, y ninguno de los eventos aprobados llegaría a otra persona.Recomiendo: sí (migración 0023) y un número de ADR para «Notificaciones».
2. ¿Papelera solo en el escritorio en 0.5.0?La web no guarda lo borrado; restaurar desde la web exigiría rutas nuevas en el servidor.Recomiendo: solo escritorio; la web muestra el aviso del boceto.
3. ¿Qué preferencias viajan?Recomiendo: la lista «Viaja» de SYNC-09; lo que depende del equipo se queda.
4. ¿Cuánto se guardan las notificaciones?Recomiendo: 90 días, máximo 500 por cuenta.
